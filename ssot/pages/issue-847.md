- [style: UX Decission for "universal" search bar](https://github.com/muhammedgaygisiz/travellers-apps/issues/847) (Issue \#847)
- Description
  - As a user I want a easy to use and understandable search experience to find faster and more intuitively what I am looking for.
  - **Problem Description**
  - As long as we can search for one entity only, there is no problem, as results are immediately correclty interpreted. However, if we provide a "universal" search, i.e. searching for a person or a restaurant or a bite is done in the same search bar, the results can be missleading.
  - **Additional information**
  - Currently know entities are: restaurant, bite and persons. We did not yet agree on a main entity, but for simplicity you can take person as being the main search entity.
  - **Ideas**
  - We could use the "instagram approach", which is, we search for the main entity, but the user can select a different entity in a tab above the search bar.
  - <img height="400" alt="Image" src="https://github.com/user-attachments/assets/11626664-c771-4987-a594-df17b20eb0f3" />
  - We can use more of a "google approach", which is, we provide a search bar, with autocompletion, but when "enter" or a "search-button" is pressed a list of results for all entites are shown. This "result-list" could be further filtered by entity type, for example.
  - <img height="400" alt="Image" src="https://github.com/user-attachments/assets/3bfd341b-b97a-4722-b384-25680eaa84f6" />
  - A mixed approach, where a clear icon symbol in front of the search result shows, what entity it corresponds to, example avatar, house and food icon.
  - **Acceptance Criteria**
  - An approach is defined that allowes the user to centrally search for different entities and easily access the results.
  - A design draft is available together with minimalistic Mockups.
