- [07 - feat: create restaurant candidates from new bite trigger](https://github.com/muhammedgaygisiz/travellers-apps/issues/944) (Issue \#944)
- Description
  - Parent: \#778
  - \#\# Goal
  - Automatically create or update restaurant candidates from new Bites when enough repeated evidence exists.
  - \#\# Scope
  - Add a Firestore trigger on Bite creation.
  - Only consider Bites not attached to a verified restaurant.
  - Use geohash bounds first, exact `200m` distance filtering second, and fuzzy name grouping.
  - Require at least `5` similar nearby unverified Bites.
  - Create or update a `restaurantCandidates` document.
  - Do not modify Bite documents.
  - Do not create a candidate when a nearby matching verified restaurant exists.
  - \#\# Acceptance Criteria
  - Fewer than `5` matching nearby Bites do not create an automatic candidate.
  - `5` or more matching nearby Bites create or update one candidate.
  - The trigger updates nearby pending candidates instead of creating duplicates.
  - Candidate links remain unidirectional.
  - \#\# Validation Notes
  - Firebase Functions build and lint should pass.
  - Emulator verification should seed nearby Bites and prove trigger behavior.
