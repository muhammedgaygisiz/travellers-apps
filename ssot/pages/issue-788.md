- [refactor(bite-tribe): dev wants to distinguish between not verified restaurant and verified restaurants](https://github.com/muhammedgaygisiz/travellers-apps/issues/788) (Issue \#788)
- Description
  - At the moment the restaurant click in the bite-tribe app navigates to the bite-tribe's restaurant page without distinguishing if it is a verified restaurant or not (restaurant exist or not - restaurantId in bite). Since we are building up the business part of the app and more restaurants will come into the system, we want to distinguish on the level of the route between verified restaurants and unverified restaurants.
  - The current route is 'path: `${PATH.BITE}/:biteId/${PATH.RESTAURANT}/:restaurantId`,' with the parameter restaurantId being the restaurantId, if the bite has a restaurantId. If the bite has no restaurantId the place name is taken as restaurantId. This is confusing and messed up.
  - Their should be 'path: `${PATH.BITE}/:biteId/${PATH.RESTAURANT}/:restaurantId`,' for the behavior so far and another 'path: `${PATH.BITE}/:biteId/${PATH.RESTAURANT}/place/:placeNameFromBite`,'. The second one, for example, has no menu, because a restaurant was not created so far.
  - For now only the route should be separated and the containers for the two components responsable for the routes. For the first case, we can leave the setup as it is. For the second we can name the component. UnverifiedRestaurant.
